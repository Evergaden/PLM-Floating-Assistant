> 版本：v0.15
>
> 建档日期：2026-08-24
>
> 适用范围：保健品开发组的选品、提需、产品开发、文案与合规、设计交付、核价备货、推广上架、生产确认工作。
>
> 文档性质：业务流程基线，同时作为后续 PLM 插件功能设计的业务依据。

## 0. 使用说明

本手册把资料中的内容分成四类，后续讨论功能时不要混用：

- **业务规则**：当前必须遵守的工作口径。
- **操作步骤**：在 PLM、群聊、浏览器或其他工具中的执行方法。
- **配置资料**：品牌、地址、单位、成分、DV、价格等可维护数据。
- **插件候选**：从流程中识别出的自动化机会，不代表已经排期或已经实现。

规则优先级暂定如下：

1. 用户后来明确确认的口径。
2. 《保健品开发组工作流程-20260606》主流程。
3. 与主流程配套的文案、命名、侵权、成分和模板资料。
4. 截图中的操作示例。
5. AI 生成结果和外部平台结果只能作为草稿，不能直接视为最终结论。

## 1. 一页式总流程

```text
选品
  -> 提需
  -> 建联商家
  -> 绑 BOM
  -> 建品
  -> 侵权图、文案、成分表审核
  -> 设计效果图与包装定稿
  -> 六面图、图包和资料审核
  -> 核价、备货
  -> 推广、上架
  -> 下单、跟货期、产前样确认
```

| 阶段 | 主要目标 | 关键产出 | 完成信号 |
|---|---|---|---|
| 选品 | 找到有热度、有销量依据的参考产品 | 参考链接、图片、关键词、卖点 | 判断为可提需产品 |
| 提需 | 把参考产品转成 PLM 新品需求 | 新品需求记录 | PLM 保存成功并获得需求编码 |
| 建联商家 | 确认包材、剂型和供应商可行性 | 供应商信息、报价、起订量、货期 | 确定合作商家 |
| 绑 BOM | 把包材和内料信息录入产品项目 | BOM 物料清单 | 纸盒、标签、印刷、其他物料信息齐全 |
| 建品 | 建立产品基础资料并完成合规内容 | 侵权图、文案、成分表、地址 | 资料提交设计 |
| 设计定稿 | 确认效果图、包装和图包 | 效果图、六面图、图包 | 设计修改/定稿信息已返回 |
| 审核备货 | 完成各节点审核，并确定价格和备货方式 | 审核结果、三档价、备货策略 | 项目流程完结或进入生产 |
| 推广上架 | 将审核通过的图包交给运营 | 推广群消息、图包 | 运营完成上架 |
| 生产确认 | 跟进货期并确认产前样 | 产前样确认信息 | 产前样审核通过 |

## 2. 角色与协作边界

资料中出现的主要协作角色如下，实际负责人以 PLM 和群聊分配为准：

- **开发人员**：查看自己的 PLM 任务；建联商家；绑 BOM；建品；跟进设计、审核、备货、推广和产前样。
- **组长/审核人员**：审核产品名称、品牌、侵权图、文案、修改理由和最终资料。
- **文案人员**：制作侵权图、标签/纸盒文案、成分表和上架标题。
- **设计部门/美工**：制作效果图、包装图、六面图和图包。
- **品控、部门经理及其他节点审核人**：按 PLM 节点完成审核。
- **运营部门**：根据图包进行商品上架，并在上架前再次人工检查。
- **供应商**：提供包材、内料、尺寸、标签、纸盒、报价和交期等信息。

## 3. 选品与提需

### 3.1 选品思路

1. 使用 Google Trends 等工具确认当前搜索趋势和主题。示例口径为美国、过去 7 天、健康相关类别；具体筛选条件可按实际产品调整。
2. 围绕主题延伸保健品的功效、卖点、适用人群和消费者付费原因，可以借助 AI。
3. 根据 AI 提供的热卖成分或关键词，到 Amazon、Temu、Pipiads、独立站、卖家精灵等平台继续筛选。
4. 重点观察产品上架时间、销量、评论、价格和同类产品密度。
5. 选中的产品必须保留参考链接、正面图和必要的截图，作为后续提需和侵权排查依据。

### 3.2 PLM 新品需求字段

| 字段 | 是否必填 | 资料来源/要求 |
|---|---:|---|
| 对标产品链接 | 是 | 参考平台的原始链接 |
| 平台来源 | 否 | Amazon、Temu、其他等 |
| 对标编码 | 否 | ASIN 或其他平台编码 |
| 对标图片 | 是 | 尽量上传产品正面、清晰、完整的图片 |
| 产品名称 | 是 | 初步中文名称，需符合命名和合规要求 |
| 关键词 | 是 | 产品搜索关键词或核心成分关键词 |
| 产品卖点 | 是 | 参考产品的主要卖点 |
| 产品功效 | 否 | 仅填写有依据、可表达的功能 |
| 产品成分功能 | 否 | 成分与功能的对应关系 |
| 其他需求备注 | 否 | 客户要求、指定卖点、特殊包装要求等 |
| 其他图片 | 否 | 最多按 PLM 页面限制上传 |

## 4. 建联商家与绑 BOM

### 4.1 判断是否为新包材/新剂型

在 PLM 任务中先判断产品是否涉及新的包材或剂型。资料中的判断口径是：

> 聚水潭没有开过的剂型或包材，视为新剂型或新包材。

如果是新包材或新剂型，需要在 1688 等渠道寻找供应商，也可以向特一确认是否已有对应资源。

### 4.2 供应商询价信息

至少收集以下信息：

- 供应商名称和联系人。
- 包材或剂型名称。
- 采购价，明确是否含税含运。
- 起订量。
- 货期。
- 是否可以开专票。
- 税率。
- 包材实拍图。
- 包材尺寸和容量。
- 内料实拍图或配方信息。
- 标签规格。
- 纸盒规格。

合作商家以综合性价比为依据，不只比较单价。

### 4.3 BOM 物料

PLM 绑 BOM 页面目前显示的物料类别包括：

- 纸盒
- 标签
- 印刷
- 其他物料

供应商提供的图片、规格和名称需要逐项对应填写，不能只上传一张总图而缺少结构化信息。

## 5. 建品与合规内容

### 5.1 侵权图制作与排查

操作步骤：

1. 截取新品表参考链接中的产品正面图，或使用开发人员提供的图片。
2. 复制正面图上的文字，排查品牌、产品名、功效词、成分词和图形标识。
3. 使用 WIPO Global Brand Database 查询可能的商标风险。
4. 判断时同时核对：
   - 权利状态是否为有效登记/Registered。
   - 注册的尼斯分类是否覆盖实际产品和使用范围。
5. 如果存在风险，修改相关词语，并保留修改原因。
6. 修改后的词语应尽量接近原意，同时具有电商搜索热度。
7. 仅调整词序、增加符号或在词尾加字母，不能视为充分规避侵权。
8. 将修改后的侵权图和注册查询截图发群，由组长审核。
9. 审核通过后，上传至新品表对应的“文案侵权排查及注册截图新”字段。

### 5.2 文案制作输入

文案制作前，先准备：

- 产品名称和品牌。
- 参考链接和对标图片。
- 成分及配比。
- 需要引用的标识。
- 产品规格和剂型。
- 制造商及对应地址。
- 保质期、原产国、警告语。
- 开发人员指定的卖点、功效和客户要求。

### 5.3 文案内容结构

纸盒/标签文案至少包含：

1. 产品名称：品牌 + 产品名。
2. 成分表：食品按开发提供的配方；化妆品使用 INCI；NDC 产品使用 UNII。
3. 警告语：使用固定模板，并根据实物适当调整。
4. 制造商及地址：根据品牌地址资料填写。
5. 保质期：食品通常 2 年，化妆品通常 3 年，其他产品按实际情况。
6. 原产国：使用固定模板。
7. 产品功效：来自开发资料或可靠参考链接。
8. 建议使用方法。
9. 产品优势。
10. 产品卖点。
11. 成分功能。
12. 销售关键词。
13. 1688 上架标题。

### 5.4 AI 文案生成约束

AI 只用于提高制作效率，不能替代最终审核。建议输出以下六部分：

- **A 使用方法**：分点列出，每点不超过 15 字。
- **B 产品优势**：4 条，每条不超过 8 个英文词或 15 个汉字。
- **C 产品卖点**：15 条；前 1–4 条可有 3–4 个词的小标题并加冒号，后续不强制加小标题。
- **D 成分功能**：3–4 条，每个成分后加冒号并说明功能。
- **E 销售关键词**：5–10 个。
- **F 建议上架标题**：参考 1688 热销词，约 30 字，不得违反广告法。

文案完成后必须经过：

```text
AI 生成 -> 人工检查 -> 发群组长审核 -> 修改确认 -> 上传新品表/PLM
```

文件名按 `日期-品牌 产品名称-产品文案` 命名。

### 5.4.1 全量案例归纳出的共通语言

已对 `E:\WXWork\1688857110932701\Cache\File\2026-08` 中的 Word 文案按人用、宠物、滴剂、胶囊、软胶囊、片剂、软糖、粉剂、茶包和口腔/日常营养等类型进行归纳。不同类型最稳定的共通处不是某一个功效词，而是“产品属性 + 日常状态支持 + 使用方式 + 固定标签信息”的组合：

本次统计得到 83 份可读取的产品文案 DOCX；目录中的 1 个 `~$` 文件是 Office 临时锁文件，不作为样本。按文档覆盖率统计，`daily` 出现在 82 份、`support` 78 份、`nutrition` 73 份、`convenient` 69 份、`Shake well before use` 68 份、`wellness` 58 份、`comfort` 56 份，说明这些词比具体功效名更适合作为跨类型的基础语言层。

- 高频中性动词：`supports`、`helps maintain`、`provides nutritional support`、`formulated with`、`designed for`、`suitable for routine use`。
- 高频状态词：`daily wellness`、`nutrition`、`balance`、`comfort`、`vitality`、`convenient`、`simple`、`routine`、`liquid drops`、`easy to use`。
- 作用分类的安全写法：免疫用 `immune wellness`，心血管用 `cardiovascular wellness`，消化用 `digestive comfort`，关节用 `joint comfort / active mobility`，秀发和肌肤用 `healthy-looking hair and skin`；这些词表示日常支持，不写成疾病、治疗或结果保证。
- 滴剂常见用法：`Shake well before use. Take the stated serving once daily. May be taken directly or mixed with food.` 其中容量、份量和频次必须以当前产品属性为准。
- 资料结构的共通顺序：产品名 → `Supplement Facts` / `Other Ingredients` → `Directions` → FDA disclaimer → `Warnings` → 经销商/地址/保质期/原产国 → A-D 双语文案；关键词和上架标题只有在资料有依据时再补。
- 需要避免从案例照抄的内容：品牌、竞品数字、未经确认的配比、`Natural/Organic/Vegan` 等属性、疾病/治疗词和绝对化承诺。案例是语言与版式证据，不是当前产品的事实证明。

### 5.5 禁用表达初始清单

以下词语和同类表达需要重点排查，不能因为 AI 输出就直接使用：

- 医疗、药品、疾病、治疗、疗效、修复等涉医涉药表达。
- 绝对化和夸大表达，如最、第一、顶级、特效、全效、速效、百分百等。
- `Natural`、`Organic`、`Vegan`、`Cruelty Free`、`Biodegradable`、`Environmentally Friendly` 等未经依据的认证或属性表达。
- `Reduce`、`Remove`、`Repair`、`Treatment`、`Therapy`、`Instantly` 等高风险英文表达。
- 与实际产品功能不一致的检测、护理、治疗或技术描述。

实际审核时以最新广告法、平台规则和公司审核标准为准。

### 5.6 产品命名规则

中文名称一般由以下结构组成：

```text
商标名 + 通用名 + 属性名
```

也可以理解为：

```text
主要成分 + 功效/用途 + 作用部位或适用场景 + 属性名
```

注意：

- 产品名称中除括号外，尽量不使用特殊符号。
- 不能使用医疗、药品、疾病、绝对化、封建迷信和虚假功效表达。
- 品牌是否可以使用 NDC，需要先对照 NDC 品牌清单。
- 品牌 LOGO、品牌归属和包装模板尽量在产品编码前确认，避免后续整套图稿和证书重做。

## 6. 成分表与规格单位

### 6.1 成分表规则

- 严格使用《膳食补充剂成分表（模板）》中的短版或长版模板。
- 正面图宣称的成分或功效，必须与成分表对应。
- 成分顺序：维生素 → 矿物质 → 其他活性成分。
- 每个部分内部按含量从高到低排列。
- 维生素和矿物质需要计算 `%DV`。
- 植物提取物等需要查询拉丁学名或规范成分名。
- 化妆品成分查询 INCI；NDC 产品相关成分查询 UNII。
- AI 可以辅助整理，但不能代替成分来源和安全性核对。

### 6.1.1 人用滴剂目标模式

- 在产品开发“编辑文案”页可使用“一键生成成分表 + 文案”目标模式；生成时自动读取当前选中 SKU 的 PLM 对标图和参考链接，不再手动上传一次生成图片。链接只作线索，不能视为已抓取或已验证的事实。
- 默认目标为人用美国膳食补充剂、60 mL、Serving Size 1 mL、Servings Per Container 60；每份活性成分合计 700 mg，标准化活性标志物比例至少 30%，辅料另列在 `Other Ingredients`。
- 活性成分行按“维生素 → 矿物质 → 其他活性成分”排序；每行同时保留中英文名、来源/部位、标准化信息和对应 Latin scientific name，导出标签时将学名放入括号。
- 目标比例按“已声明的标志物 mg ÷ 活性成分合计”计算，是配方草案检查项，不替代供应商 COA、身份鉴定、稳定性、密度、溶解/悬浮和法规审核。
- 实际案例与抽象模板发生冲突时，优先采用案例中已验证的 `Supplement Facts`、`Other Ingredients`、摇匀和用量呈现方式；不得照抄案例品牌、禁词、数字或未经证实的功效。

后续开发插件时，不能只保存整段显示文字，建议同时解析并保留：

- 模板类型、工作表名称和模板版本；
- 每份用量、每罐份数；
- 活性成分、非活性成分/其他成分的分组；
- 成分英文名、来源/拉丁学名、部位、提取比例；
- 含量数值、单位及 `CFU/IU` 等特殊计量；
- 原始文本，用于回溯和人工复核。

注意：该模板库中存在标点、空格、标题（`Active/Ingredients/Other/Inactive`）和份量写法的差异。选择模板时应以产品剂型、目标市场和合规审核结果为准，插件只能辅助套版、解析和检查，不能根据案例自动判定合规。

| 类型 | 正面/背面示例 | 适用场景 |

统一要求：

- 单位使用英文大写。
- 毫升或克前统一加 `NET`。
- 毫升和克必须同时显示美制盎司。
- 换算后接近整数时显示整数；小于 1 或有尾数时保留两位小数。
- 多个产品组成套装时，逐个列明单位和数量。

## 8. 定价与备货规则

### 8.0 定价输入与自动计算边界

产品定价功能必须区分“人工确认值”和“系统计算值”：

- **人工填写字段**：采购价（含税运）、国内一档价格、国内二档价格、国内三档价格。
- 系统可以根据规则给出建议价格、匹配价格表、提示超出范围或校验异常，但不能覆盖人工填写的采购价和三档价格。
- 参考表中的采购价和三档价格是历史/标准参考值；实际项目仍以开发人员填写并确认的值为准。
- 截图中的“销售底价”与三档价格的推导关系尚未确认，暂不在插件中写死计算方式。
- 所有价格保存时应同时保留来源：人工填写、价格表匹配、公式计算或上级确认。

### 8.1 新品三档价格

基础公式：

```text
采购价（含税运） × 2 + 2
```

当前执行口径：

- 采购价统一理解为含税、含运费的采购成本。
- 对应剂型、规格和采购价在参考表覆盖范围内时，优先采用表格中的三档价格作为建议值。
- 表格没有对应规格、采购价超出表格范围或资料标记“问上级”时，进入公式计算或上级确认流程。
- 公式 `采购价 × 2 + 2` 当前只记录为基础计算规则；它是销售底价、三档价格的中间值，还是需要再生成三档价格，尚未确认，不能擅自取整或自动倒推。
- 三档价格的具体档位条件、顺序和适用客户/订单条件尚未定义；插件应保留一档、二档、三档三个独立输入框，不把 `6 / 7 / 8` 等文本自动倒序或改写。

  -> 以对标图片文字为主要证据，AI 提取全部可见文字、归一化坐标、风险类型和置信度
  -> 识别产品作用，生成中文朦胧产品名；英文产品名优先采用包装主标题
  -> 服务端与本地拦截禁词/品牌词/格式异常
  -> 生成左原图、右修改对照图
  -> 人工修改并下载 PNG
  -> 生成 A-D 文案 DOCX
  -> 打开产品详情预填表，补充采购价/三档价格和缺失字段
~~~

编辑文案页内的人用滴剂目标模式流程为：

~~~text
当前选中 SKU 的对标图 + 已读取产品类型 + 所选成分表/文案模板
  -> 第一步：只生成 Supplement Facts 和 Other Ingredients 成分表草案
  -> 人工编辑并校验活性合计、标准化标志物比例、拉丁学名括号和必填项
  -> 确认成分表后，第二步才把确认后的成分、用量和 Other Ingredients 交给 A-D 文案生成
  -> 套用所选 DOCX 文案模板生成文案文件；Supplement Facts PDF 仅在校验通过后导出
  -> 供应商 COA、配方工艺和法规人员人工复核
~~~

标准要求：

1. 原图必须保留，不生成清除文字后的包装图。
2. 每个修改项必须有原文字、红框坐标、编号、英文修改和中文翻译。
3. 侵权图流程不要求读取成分；成分缺失不能阻止图片文字筛查。
4. AI 结果是初筛和草稿，不等同于商标、广告法或平台的最终结论。
5. v1 不自动访问或绕过 WIPO 等外部查询网站；需要查询时仍按人工流程留存查询证据。
6. 分析后可手动修改原图文字、英文修改、中文修改和红框归一化坐标，也可手动新增或删除风险项，再重新生成对照图。
7. 图片结果只保存在本地历史记录和下载文件中，不回写 PLM。
8. 预览区支持独立滚动查看完整对照图，不能把浮窗当前可视范围误认为图片内容已截断。

产品命名参考：已学习 `商品资料_20260825115049_187484352_1.xlsx` 中的中文命名节奏，例如“犬猫益生菌滴剂”“狗狗助睡眠滴剂”“宠物口腔除臭滴剂”。这些名称只用于学习“适用对象 + 朦胧作用/状态 + 剂型”的表达结构，不得照抄其中产品事实、品牌、成分或功效；英文产品名不从该表翻译，优先取对标包装可见的大标题。

### A.4 A-D 文案 DOCX 字段映射

| 字段 | 数量 | 英文列 | 中文列 | 规则 |
|---|---:|---|---|---|
| A. 产品功效 | 4 条 | 第 2 列 | 第 3 列 | 每条一句，中文不超过 20 字 |
| B. 产品优势 | 4 条 | 第 2 列 | 第 3 列 | 中文不超过 15 字，英文不超过 8 词 |
| C. 产品卖点 | 15 条 | 第 2 列 | 第 3 列 | 前 1–4 条可带 3–4 词小标题 |
| D. 成分功能 | 当前 SKU 全部有效成分 | 第 2 列 | 第 3 列 | 成分名称必须与 PLM 输入逐项一致 |

第四列留白；A-D 之外的产品名称、使用方法、关键词、1688 标题等暂不生成正文。模板示例正文先清空，再按行号、换行和四列表格结构填充。英文采用简洁的欧美电商表达，但必须以输入证据为边界。

### A.5 成分来源与合规提醒

- 成分优先取当前 PLM 商品详情和产品文案接口；缺失时复用现有成分表 PDF 标准化读取逻辑。
- 只把当前 SKU 的有效成分传给文案生成，不读取附件中其他产品的示例成分。
- 成分中文、英文和功能应保留来源快照，便于人工回查。
- 禁止品牌词、禁用词、涉医涉药表达、绝对化/夸大表达、虚构成分、星号和空行进入最终 DOCX。
- FDA、INCI、平台广告规则和商标结论仍需人工核验；插件只做资料整理和风险拦截。

### A.6 本地文件、历史和回写规则

- 文案内置模板版本为 builtin-v1；成分表内置 `人类食品成分表1216.xlsx` 和 `宠物食品成分表1模板.xlsx`，产品开发页按“人类食品/宠物食品”分开选择工作表，也可以添加本地 XLSX 模板。
- 成分表编辑器只展示当前工作表的可编辑单元格；修改自动保存到本地草稿，点击“保存本地”或“下载 Excel”时生成副本，原始模板、版式和图片不直接改写。
- 侵权对照图下载为 SKU-infringement-comparison.png；文案下载为 SKU-copywriting-A-D.docx。
- 本地历史最多保留 8 条，保存 SKU、时间、文件名、风险条数或文案模板版本；产品图历史可点击查看和下载已保存 PNG；不上传到 PLM。
- 侵权图失败、缺少 SKU 或缺少对标图片时停止图片流程并提示人工处理；DOCX 仍要求当前 SKU 有效成分、模板字段和校验全部通过。
- 人工审核通过后，仍按原流程把图片、文案和审核证据提交到对应 PLM 字段；v1 不自动完成这一步。

### A.7 产品详情预填表与只读接口

开发任务右侧详情复用设计任务的“左侧 SKU 列表 + 右侧详情”布局，但使用产品开发专用详情渲染。选择 SKU 的读取阶段只使用 GET 请求，不调用建品、绑 BOM、上传、同步或提交接口；只有用户主动点击建品区或 BOM 区域各自的保存按钮，才进入对应写入流程。开发详情不展示日常设计任务的纸盒编码、通用尺寸、导出和设计操作；这些字段若属于 BOM 原始数据，仍在对应 BOM 表单中保留，便于人工核对：

- 建品基础信息：SKU、项目编码/ID、产品 ID、产品版本 ID、分类、中文名、英文名、品牌、产品类型、开发人员和任务状态。
- BOM 绑定明细的全部读取字段：绑定 ID、BOM 类型、物料/成品编码、名称、分类、规格/属性、物料类型、默认供应商及 ID、价格、用量和长宽高。
- 当前产品分类模板的全部建品字段；`is_must` 字段会标记“必填”。当前宠物保健品接口样本的必填项包括规格型号、毛重、外包装长/宽/高/体积、产品产线、最小起订量、成本价、标准装箱数、箱规、箱重、创建组织、使用组织、采购组织，共 15 项。
- 资料字段状态：成分表 PDF、条码文件、产品正面图、产品文案 DOCX 是否已读取。用户已确认“宠物牙齿滴剂.pdf”属于成分表 PDF，不应当当作条码文件。

价格区分如下：

| 表单字段 | 来源和处理 |
|---|---|
| 采购价（含税运） | 单独的本地参考输入，不与成本价混用；由开发人员填写 |
| 成本价 | PLM 建品必填字段，读取后展示；是否等同采购成本由人工确认 |
| 国内一档/二档/三档价格 | 独立本地参考输入，三档价格由开发人员填写；系统只做表格匹配和公式建议 |

上述建品基础信息、全部建品字段、采购价/成本价/三档价格、BOM 字段和资料文件值均以可编辑表单展示。已读取值可以继续修改，空白字段可以先填写；详情编辑和纸盒/标签物料预填按 SKU 保存在本地缓存。建品资料与 BOM 绑定是两个独立保存区：建品区的“保存建品到 PLM”只调用建品详情接口，BOM 区的“保存 BOM 到 PLM”只调用物料草稿、绑定和价格接口；两者互不代保存，所有结果仍需人工复核。

#### A.7.1 建品资料独立保存

- 建品资料对应 PLM 的建品详情页，读取 `GetProductDetailInfo` 和 `GetProductDetailContent`，保留当前分类模板返回的完整 `attr_values`（包括空值和语言项），在建品区独立编辑。
- 用户点击“保存本地”只更新当前 SKU 的本地缓存；点击“保存建品到 PLM”才调用 `POST /api/ChemicalNewDevTask/SaveProductDetail`，请求体为 HAR 中的 `{ id: 项目ID, product: {...} }` 结构。
- 建品保存只更新产品详情字段、语言名称和产品版本状态，不调用 `ChemicalNewBom/*` 接口；失败时保留本地编辑内容，不改变 BOM 保存状态。
- 创建组织、使用组织和采购组织按 HAR 的 PLM 默认值带出：前两项为“西月集团”（值 `1`），采购组织为“西月总部”（值 `1`），界面不要求重复填写。

### A.8 纸盒与标签物料预填规则

产品开发 SKU 详情新增独立的“填写 BOM 物料”区域，位于建品资料下面。默认先保存本地；人工点击“保存 BOM 到 PLM”后，才执行创建/更新纸盒、标签物料、绑定项目和保存价格。该区对应 PLM 的绑定 BOM 页面，与上面的建品详情页分开保存。字段规则来自 `plm.westmonth.com食品返工绑定bom.har`、`plm.westmonth.com宠物返工绑定bom和建品.har` 以及 PLM 页面截图。

#### A.8.1 命名和规格型号

以当前产品中文名为基础；如果 PLM 建品中文名为空，使用开发任务名称，再没有时使用本地填写的产品中文名。

| 物料 | 默认物料名称 | 默认规格型号 | PLM 分类 |
|---|---|---|---|
| 纸盒 | `产品中文名 + 纸盒（食品两年）`；选择“需内卡”时为 `产品中文名 + 纸盒（内卡 食品两年）` | `成品规格，长x宽x高cm` | `包材 / 纸盒 / 白卡 / 白卡` |
| 标签 | `产品中文名 + 标签（圆弧 食品两年）` | `成品规格，长x宽cm（玻璃加粘）` | `包材 / 标签 / 标签 / 标签` |

已有 PLM BOM 的名称和规格先保留原文；未保存过的名称和规格由上述规则生成，用户可以直接手动修改。修改过的字段标记为本地人工值，后续尺寸或计算器选项变化不会覆盖手动名称/规格。

#### A.8.2 HAR 对应的默认绑定字段

| 物料 | `category_id` | `material_type` | 默认供应商 | 绑定默认 |
|---|---:|---:|---|---|
| 纸盒 | 114 | 0 | 广州美多印刷有限公司-纸盒（80000249） | `type=2`、`usage_value=1`、`pics=[]` |
| 标签 | 119 | 1 | 汕头市柠彩文化传媒有限公司-标签（80000173） | `type=2`、`usage_value=1`、`pics=[]` |

项目 ID 和 `product_code` 从当前开发 SKU 自动带出。未点击按钮时不发起写入请求；点击“保存到 PLM”后按下列接口顺序执行：

1. 若项目尚未绑定产品，调用 `GetProductList?type=1&codes_precise=SKU` 找到产品主 ID，再调用 `AddBatchProjectPMJoin` 绑定成品。
2. 对纸盒和标签分别调用 `SaveMaterialDraftOfProduct`，提交物料名称、项目 ID、分类、规格型号、`w/l/h` 尺寸、SKU、供应商、采购价和物料类型。
3. 重新读取 `GetProjectPMJoinList`，取得新物料对应的 BOM 绑定行 ID；如缺少绑定行，再调用 `AddBatchProjectPMJoin` 补绑。
4. 调用 `MaterialBatchSaveAndSyncToProduct` 保存完整 BOM 行，`effect_picture_files` 使用空数组；项目未建品时，PLM 返回“无法同步图片”只作为提示，不判定 BOM 保存失败。
5. 调用 `SaveBomPricing` 保存已有 BOM 行中可计算的采购价。

写入成功或失败都会在 BOM 区显示结果并写入本地缓存；BOM 写入不会自动上传效果图或修改建品字段。建品字段如需写入，必须单独点击建品区的“保存建品到 PLM”。

#### A.8.3 纸盒价格

纸盒详情卡保留 PLM 纸盒计算器的采购数量、是否多页、是否需内卡、是否需加厚选项。采购数量档位和计算系数如下：

| 采购数量 | 系数 | 最低价 |
|---|---:|---:|
| 0–1999 个 | 4.5 | 0.18 |
| 2000–4999 个 | 4 | 0.14 |
| 5000–9999 个 | 3.5 | 0.11 |
| 10000–19999 个 | 3 | 0.072 |
| 20000–49999 个 | 3 | 0.07 |
| 50000–99999 个 | 3 | 0.068 |
| 100000 个以上 | 3 | 0.065 |

输入长、宽、高均为厘米：

```text
基础价 = max(
  ((2 × (长 + 宽) + 1.5) × (高 + 2 × 宽 + 3) ÷ 10000 × 数量系数),
  最低价
)
加厚：基础价 × 1.2
内卡：结果 × 2
多页：结果 + 0.02
最终保留 2 位小数
```

#### A.8.4 标签价格

标签只需手动填写长、宽二维尺寸，单位为厘米：

```text
标签价 = max((长 ÷ 100) × (宽 ÷ 100) × 9, 0.04)
```

结果最多保留 6 位小数，不使用纸盒的采购数量、内卡、加厚和多页选项。HAR 中 `12 × 5.2cm` 标签计算为 `0.05616` 元，与实际保存请求一致。

#### A.8.5 本地缓存和后续 PLM 操作

- 尺寸、选项、生成的物料名称、规格型号和计算价格按 SKU 保存在本地详情缓存中。
- 点击“刷新资料”重新读取 PLM 时，保留本地物料预填值，不被只读接口覆盖。
- “保存 BOM（本地）”只保存本地缓存；“保存到 PLM”会先校验纸盒/标签名称、规格、尺寸和价格，再按 HAR 对应流程写入。
- PLM 返回“项目未建品，无法同步图片”时，BOM 和价格仍按接口结果反馈；图片同步需待项目建品后由原 PLM 流程处理。
